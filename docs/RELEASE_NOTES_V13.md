# ProjectAgain v0.13 — 개인정보 삭제 · 인수 보고서 필수화 · GitHub CI 증거

- v0.12의 거래·협상·로드맵·지원 API와 DB 기록을 보존하여 확장합니다.
- 계정 설정에서 비밀번호 확인 및 `계정 탈퇴` 재입력 후 탈퇴·개인정보 삭제를 요청할 수 있습니다.
- 가입 원본 이메일, 암호·토큰, GitHub 연결, 외부 에이전트 승인, 매물 노출, 비공개 파일 접근 등을 정리합니다.
- 영속 기술 ID·시연 거래 기록은 개인정보·설명 문구를 가린 뒤 보존합니다. 실제 대금이나 법률상 권리 이전은 여전히 없습니다.
- 파일 저장소 삭제는 DB에 재시도 가능한 작업으로 등록합니다. 메일 알림 워커가 SMTP 설정 여부와 관계없이 삭제 큐를 함께 처리하며, 수동 일회 실행도 가능합니다.
- 모든 매물에 `listing_readiness_reports`를 발행합니다. 수동 등록·이전 버전 등록에도 보고서가 반드시 존재하도록 새 등록 시 저장하고 마이그레이션으로 일괄 생성합니다.
- ZIP과 GitHub는 기존 안전한 정적 검사 결과를 포함합니다. GitHub는 가져온 정확한 커밋 SHA의 GitHub Actions **기록**을 조회합니다. 외부 에이전트가 제출하고 공개된 실사 기록의 메타데이터도 보고서에 반영합니다.
- GitHub CI 성공을 실제 실행·테스트·보안·판매권리 인증으로 오인하지 않게 출처·범위·미확인 사항을 표시합니다.
- 플랫폼 서버에서는 타인의 소스 파일을 절대로 실행하지 않으며, 실제 구동 검증을 위한 격리 실행 환경은 별도 과제로 남습니다.

## API

- `GET /api/v1/auth/privacy/summary` — 내 탈퇴 시 영향 범위 (본인 세션)
- `POST /api/v1/auth/privacy/delete` — `{ "password": "...", "confirmation": "계정 탈퇴" }` (본인 세션 및 CSRF, 관리자 제외)
- `GET /api/v1/listings/{id}/takeover-report?include_demo=true` — 매물 접근권한과 동일한 보고서, 모든 매물에서 `available: true`
- 기존 `/listings/{id}/source-summary` 및 `/source-summary/reanalyze` 는 호환 유지

## 개인정보·운영 제한 사항

현재는 법적·실무적인 개인정보 파기 전 과정이 자동 완성됐다고 주장하지 않습니다. 삭제한 DB의 물리적 백업·관찰 로그·이미 발송된 이메일·외부 GitHub 앱 설치 권한은 별도의 보존·삭제 정책으로 관리해야 합니다. 법률상 보존 의무가 있는 실제 거래를 도입하기 전 법무 검토, 목적별 보유기간, 별도 보존 저장소 및 유예 절차를 구현해야 합니다. 이 버전의 거래는 DEMO에 한정합니다.
