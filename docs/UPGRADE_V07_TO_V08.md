# ProjectAgain v0.7 → v0.8 업그레이드

1. **백업:** Replit 기존 프로젝트 전체, PostgreSQL DB, Replit App Storage를 먼저 각각 백업한다. 운영 DB는 초기화하지 않는다.
2. 서비스 중지 후 v0.8 ZIP의 `projectagain/` 폴더 내 파일들을 기존 동명 프로젝트 폴더에 덮어쓴다. `.env`, Replit Secrets, 사용자 DB, Storage 볼륨을 삭제하지 않는다.
3. 개발용 Shell에서 `cd ~/workspace/projectagain && bash scripts/setup_replit.sh` 실행. Python 패키지 설치, React 프론트엔드 빌드, Alembic 업그레이드가 순서대로 진행된다.
4. `cd ~/workspace/projectagain/backend && ../.venv/bin/python -m alembic current`에서 `0006_deal_management` 확인.
5. `cd ~/workspace/projectagain && bash scripts/run_replit.sh` 로 앱 실행.
6. 이메일 알림을 원한다면 기존 `SMTP_*` 설정과 별도 `scripts/run_notification_worker.sh` 워커가 필요. 내부 알림은 워커 없이 유지.
7. 다른 두 개 계정과 관리자 계정을 준비하여 테스트 매물을 생성한다. 반드시 **시연 매물/시연 거래**로 점검하고 실금전 거래를 만들지 않는다.

## E2E 점검

- 구매자가 제안 → 판매자가 수락. 거래 화면에서 자동으로 생성된 조건 확인서, 해시, 포함·제외 자산을 확인.
- 판매자가 먼저 조건 확인. 구매자 확인 전 인계 시작과 원본 파일 공유가 409로 차단되는지 확인.
- 구매자도 확인하면 인계 시작·기존 인수인계 체크리스트·자료 공유가 동작하는지 확인.
- 시연용 조건서 `.txt`를 내려받아 고정된 금액·권리 유형·당사자 확인 시각·해시를 확인.
- 취소를 요청한 사용자가 직접 승인할 수 없는지 확인. 상대방이 승인하면 예약 매물이 다시 공개되는지 확인.
- 다른 거래에서 분쟁 접수 → 상대방 답변 → 관리자에서 인계 재개/취소를 결정. 기록과 알림을 확인.
- 제3자에게 조건서·거래 이력·분쟁이 노출되지 않는지, 에이전트 토큰으로 확인할 수 없는지 확인.

## 주의

- 새 기능은 실결제·전자서명·계약 유효성 보장·저작권 이전 기능이 아니다.
- 이전 버전 거래의 단순 `CANCELLED`/`DISPUTED` 전환 호출은 변경되었다. 기존 프론트는 반드시 v0.8로 함께 업데이트해야 한다.
- 과거 이미 완료된 시연 거래는 변경하지 않으며, 이전 거래에 새 계약 기록이 없으면 당사자가 명시적으로 준비해야 한다.
- 파일이 실제로 다운로드된 이후에는 거래 취소로 파일 사본을 회수할 수 없다.
- 프론트엔드 브라우저 동작과 실제 Replit PostgreSQL·SMTP 통합은 업그레이드 후 실환경에서 별도 확인 필요.
