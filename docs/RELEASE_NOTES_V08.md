# ProjectAgain v0.8 — 거래 조건·인수인계·취소·분쟁 관리

## 개요

v0.7의 매물·GitHub/ZIP·문의·알림·기존 모의 제안/인수인계를 그대로 유지하면서,
**실제 결제 파트너를 선정하기 전에 검증 가능한 시연용 거래 관리 시스템**을 개발했다.

**이 버전에는 결제, 에스크로, 전자서명 서비스, 실제 저작권 이전, 환불 및 정산이 전혀 없다.**
임의 계좌 이체 안내나 사용자 자금 보관 기능도 제공하지 않는다. 모든 금액은 거래 조건 기록일 뿐 청구하지 않는다.

## 추가 기능

1. 제안 수락 시 가격·권리 유형·포함/제외 자산·기술적 결함·인계 기간·제안 추가 조건을 고정한 SHA-256 스냅샷 자동 생성. 기존 v0.7 거래는 당사자의 명시적 준비 요청으로 생성.
2. 구매자 및 판매자 각각의 사람이 로그인한 상태에서 시연 목적과 거래 조건을 확인. 다른 내용의 해시를 확인하려 하거나 동일 사용자가 반복 확인하면 거부. AI 에이전트는 확인 불가.
3. 조건 기록을 UTF-8 `.txt` 파일로 내려받기. **법적 효력 보장 전자계약서가 아니라 시연용 거래 조건 확인서**로 명시.
4. 양측 조건 확인 전에는 인계 단계 변경 및 원본 자료 공유 불가. 양측 확인 후 기존 파일 접근·체크리스트·구매자 최종 확인·보완 요청 흐름 그대로 사용.
5. 한쪽이 취소 사유 등록 → 상대방의 수락 또는 거절. 요청자가 스스로 취소 승인 불가. 수락 시 `CANCELLED`로 전환, 한 번만 판매하는 매물의 예약 해제, 미만료 자료 공유 권한 철회. **이전에 내려받은 자료는 기술적으로 회수할 수 없음.**
6. 거래 당사자의 분쟁 접수(사유·설명·선택적 참조), 상대방 답변, 관리자 검토. 분쟁 중에는 인계 단계 변경 중단. 관리자가 `RESUME_HANDOVER` 또는 `CANCEL_DEMO`로 결정. 관리자 본인의 분쟁은 직접 결정할 수 없음.
7. 거래 타임라인, 감사 로그, 내부 알림+선택적 이메일 대기열 연동.
8. `거래 인수인계` 화면에 거래 조건 확인·시연용 문서 다운로드·취소·분쟁·이력 화면 추가. 관리자 화면에 분쟁 접수함·거래 목록·상세 조회 추가.

## 하위호환/변경사항

- 기존 `POST /transactions/{id}/transition` 의 `DISPUTED`, `CANCELLED` 단일 변경 요청은 **409**를 반환하며 신규 분쟁·취소 API를 이용해야 한다.
- 기존의 판매자 `HANDOVER_IN_PROGRESS`, `HANDOVER_REVIEW`, 구매자 `DEMO_COMPLETED` 전환은 **양측 거래 조건 확인 후에만** 가능.
- 기존 v0.7 거래는 `POST /transactions/{id}/agreement/prepare` 후 양측 확인 가능. 이미 종료된 거래의 상태는 이전 그대로 유지.
- PostgreSQL 마이그레이션 `0006_deal_management`는 기존 거래/매물/사용자를 삭제하거나 변경하지 않고 새로운 테이블 4개만 추가.
- 사용자 승인 없는 외부 AI 에이전트의 거래 조건 확인·분쟁 결정 불가. AI 모델을 ProjectAgain에 내장하지 않음.

### 제품 경계

이 기능은 인수인계·조건 합의 **시연과 로그 보존**을 위한 것이다. 실거래 출시 전에는 결제·수탁·대금 보호 사업자 적합성, 계약법적 문서 효력, 소비자 보호/세금/개인정보·전자상거래 의무 등을 별도로 검토해야 한다.
