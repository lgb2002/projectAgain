# ProjectAgain v0.12 — 통합 거래·인수 작업실

기준일: 2026-11-13. 기반 버전: v0.11. 배포 단계: **DEMO/검증용**.

## 무엇이 바뀌었나

### 1. DEMO 거래와 매물 상태 완전 분리

- 판매자의 시연 제안 수락, 구매자의 시연 인수 완료, 시연 거래 취소가 실제 매물의 `status`를 변경하지 않음.
- 시연 거래의 `exclusive_guard_listing_id`는 NULL로 둠. 서로 다른 구매자의 모의 거래는 각각 독립적으로 진행할 수 있으나, 동일 구매자·매물의 진행/완료 모의 거래 중복은 차단.
- `listing.version`이 제안 당시와 달라지면 새 조건 확인을 요구(409). 같은 협상의 오래된 제안을 수락할 수 없음.
- 이전 v0.11에서 이미 `RESERVED`/`CLOSED`로 바뀐 매물은 **자동으로 ACTIVE로 되돌리지 않음**. 실제 수동 조치/다른 사유가 있을 수 있으므로 운영자가 거래 이력과 매물 권리를 확인한 뒤 복구.

### 2. 협상 과정 개선

- `OfferThread` 단위로 구매자·판매자 쌍의 역제안 이력을 묶음.
- 구조화된 제안 조건: 가격, 권리 유형, 포함 자산, 제외 자산, 인계 기간, 판매자 지원 기간·건수·범위, 답변 목표(보장 아님), 별도 조건.
- 지원 기본 권장: 0일/0건, 7일/3건, 14일/5건, 30일/10건. 건수는 양측의 명시적 합의로 조정 가능.
- 새 매물 상세의 제안 작성, 협상 타임라인과 차이 비교 화면, 판매자 응답/역제안/거절, 시연 수락 확인.
- v0.11 자유 형식 제안은 내용과 기록을 보존하며, `schema_version=2`가 없으면 기존 약정 내용에 대한 추정·보증을 제공하지 않음. 기존 외부 에이전트의 API 호환 경로는 유지.

### 3. 인수 합의 및 지원 약정 고정

- 거래가 성립하는 순간 `DealAgreement.snapshot`에 선택한 V2 가격·자산·권리·지원 조건을 고정하고 SHA-256 해시로 기록.
- `SupportPolicySnapshot`에 승인된 지원 기간·범위·건수를 별도로 고정. 공개 매물의 추후 수정이 이미 수락한 조건을 덮어쓰지 않음.
- 지원 기간은 구매자의 `DEMO_COMPLETED` 단계 확인 후 시작. 일수 0은 일반 기술 지원 없음.
- 예전 자유 형식 합의는 지원 미확인으로 표기하고 일반 무료 기술 지원을 0일/0건으로 제한; 인수 자산 누락·권리 문제는 별도 접수 가능.

### 4. 초보자 친화적인 개발 로드맵

- 구매자가 경험 수준(`NONE`, `BASIC`, `INTERMEDIATE`, `ADVANCED`) 및 안내 길이(`BRIEF`, `STANDARD`, `DETAILED`)와 목표를 프로젝트별로 기록.
- 작업 단계·선행 조건·체크리스트·전문가 도움이 필요한 경우를 기존 정적 분석과 구매자 설정에 기반해 표시. LLM 호출 또는 자동 코드 실행은 없음.
- `BLOCKED` 상태의 원인을 필수 선택하여 저장하고 해결 가이드에 반영. 완료 작업, 기존 메모, 사용자 추가 작업은 유지.
- 개별 작업과 사후 지원 사례를 연결해 작업에서 직접 지원 요청으로 이동.

### 5. 판매자 지원 센터 / 프로젝트 작업실

- 구매자는 약정 범위 내 일반 기술 문의(기간·건수 확인), 인수 자산 누락, 권리 문제, 별도 협의 건을 접수할 수 있음.
- 판매자와 구매자는 요청별 텍스트 메시지 작성, 상태·버전 충돌(409) 확인. 신규 일반 문의는 기한 종료 시 차단하지만 기접수 문의 답변은 가능.
- 일반 기술 문의만 약정 건수를 차감. 누락 자산·권리 문제는 별도로 관리하며 판매자가 임의로 일반 문의로 재분류할 수 없음.
- 구매자만 해결 완료 확정. 양측의 관리자 검토 요청, 관리자의 증빙 열람·추가 정보 요청·미해결 종결과 알림/감사 기록 포함.
- 거래 페이지에 조건·인계·구매자 로드맵·판매자 지원을 묶고, 관리자 페이지에 분쟁 검토 섹션 추가.

## 데이터/운영 주의

- 마이그레이션: `0008_integrated_workspace`. 기존 레코드 삭제 없음; 과거 제안을 협상 스레드에 연결. 원본 데이터가 없거나 깨진 레코드는 운영 전 검사 필요.
- 지원 메시지/요청 **첨부파일은 보안상 비활성화**. 텍스트 입력에서도 비밀키 패턴 탐지를 하지만 완전한 개인정보 유출 방지 시스템은 아님.
- 지원 정책은 시연 약정이며 집행 가능한 상용 계약/청구/환불·에스크로가 아님.
- 별도 AI 에이전트의 `/api/v1/agent/*` 계약 및 인간 승인 흐름 유지. 플랫폼 자체의 AI 모델 호출 없음.
- **남은 출시 과제:** PostgreSQL 마이그레이션, 동시 요청/데이터 잠금 부하 테스트, SMTP 실수신, GitHub App 비공개 연결 및 권한 철회, 원본 자료 이동·보안, 사용자 신고·탈퇴, 실결제·대금보호·법적 양도 절차, 실제 브라우저/모바일 검수.
