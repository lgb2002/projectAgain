# ProjectAgain v0.11 — 전체 UI·UX 정돈 및 알림 동기화

## 목적

v0.10의 매물·GitHub/ZIP 가져오기·비공개 파일·시연 거래·인수 후 로드맵·외부 에이전트 API를 유지하면서, 기능 단위로 누적된 화면을 **사용자 행동 및 현재 해야 할 일** 중심으로 정리한다.

## 주요 수정

### 알림 정확성 및 조작

- 헤더 배지와 알림함은 `NotificationProvider`라는 **단일 클라이언트 상태**에서 읽음 여부와 개수를 관리한다.
- 개별 읽음 API 성공 후 목록·배지 동시 갱신. 실패 시 경고 및 서버 재조회.
- 읽지 않은 알림만 보기, 오래된 알림 추가 로드, 읽음 확인 후 관련 화면으로 이동.
- 창이 다시 활성화되거나 브라우저 포커스가 복귀하면 알림을 다시 조회. 45초 주기로도 갱신.
- 서버 `GET /api/v1/notifications`의 `unread`는 **사용자 전체 미읽음 알림**에 대한 SQL 집계. 목록에 표시된 최근 100건만 세지 않음.
- 기존 알림 API는 `offset`(0 이상) 및 `limit`(1~100) 페이지네이션, `has_more`를 추가한다. 기본 응답의 `items`, `unread`는 기존과 호환된다.
- 이메일 수신 설정은 별도 `/settings` 화면으로 이동(서버 API·SMTP 워커 불변).

### 헤더·메뉴·대시보드

- 헤더는 `프로젝트 탐색 / 프로젝트 판매 / 내 프로젝트` 3가지 주요 동작 중심.
- 계정·AI 연결·이메일 알림 수신 설정을 `/settings`로 분리.
- `내 프로젝트`는 판매·구매/인수·관심 프로젝트를 주요 탭으로 구성하고, 제안·문의·알림은 보조 동선으로 배치.
- 기존 딥링크 `dashboard?tab=offers`, `?tab=inquiries`, `?tab=transactions`, `?tab=notifications`, `/operations`는 유지.

### 탐색·상세

- 검색창, 유형, 상태는 바로 노출하고 권리 유형·가격은 접을 수 있는 상세 필터로 구성.
- 매물 상세는 간략한 구매 판단 요약 후 `소개 / 기술·인수 준비 / 문의 / 권리·검증` 탭으로 구분.
- 코드 실행 및 판매 권리 검증을 자동 인증으로 표현하지 않는다. 시연용 제안 안내 유지.

### 판매 등록

- 기존 자동 임시저장, 단계 검증, GitHub/ZIP 초안 적용 보호 기능 유지.
- 초안 저장 직후 `/sell/:id/complete`로 이동: 이미지, 시연 URL·영상, 주요 기능을 추가하고 **같은 단계에서 관리자 검토 요청**.
- 페이지 새로고침을 해도 판매자의 매물 ID를 통해 마무리 화면 재진입 가능. 내 매물에서도 마무리 링크 제공.
- 시연 정보 입력 중 아직 저장되지 않은 변경사항이 있으면 검토 요청 버튼 비활성화.
- 이미지 업로드나 편집이 시연 URL 입력값을 덮어쓰지 않도록 수정.
- 검토 요청 직전 현재 서버 매물 버전을 다시 읽어 낙관적 동시성 오류 방지.
- 여전히 이미지 업로드는 매물 초안 생성 이후에 수행한다. 이미지 저장 자체를 단일 API 트랜잭션으로 통합한 것은 아니다.

### 거래·관리자·고급 설정

- 거래 단계/다음 행동은 기존과 같이 상단에, 취소·분쟁·처리 이력은 접기 화면에 배치. 처리 중인 취소·분쟁은 자동으로 열린 상태로 시작.
- 관리자 화면은 검토 대기 큐 우선, 나머지 매물/신고는 펼쳐 보기. 비공개 파일·에이전트·분쟁 관리 기능 유지.
- 매물별 비공개 파일 관리 버튼은 해당 프로젝트가 이미 선택된 `/operations?tab=files&listing=...` 경로로 이동.
- '거래 업무실'처럼 범용적인 제목 대신 현재 고급 화면의 동작을 설명하는 제목 사용.
- 카드·입력창·버튼·타이포·여백·모바일 레이아웃의 공통 시각 규칙을 정리하고 불필요한 히어로 장식을 숨김.

## 그대로 유지한 정책

- 플랫폼 내부에서 AI 모델을 실행하지 않는다. 외부 에이전트는 별도 서비스로 유지한다.
- 실제 결제, 정산, 에스크로, 법적 권리 이전은 제공하지 않는다.
- 원본 소스는 공개 매물에서 다운로드할 수 없다. 인수 자료는 기존 권한 및 승인 절차를 거친다.
- 등록 매물의 관리자 검토·승인 절차는 유지한다.
- 기존 DB 테이블 및 Alembic revision에 변경이 없다.

## 검증 범위

- **백엔드 77개 테스트**를 파일별 그룹으로 나누어 모두 통과. 추가 알림 테스트는 `test_notification_unread_v11.py`.
- 신규 알림 집계 105건, 개별 읽음 중복 처리, 타 사용자 읽음 금지, 100건 뒤 알림 조회, 전체 읽음 처리 확인.
- 전체 TS/TSX 파일의 TypeScript 파서/트랜스파일 구문 검사를 통과. 전체 CSS는 PostCSS 구문 검사 통과.
- 이 실행 환경에서는 npm lockfile의 `package-firewall.replit.internal` 패키지를 다운로드할 수 없어 **정식 프론트엔드 `npm run build`, TypeScript 전체 타입 검사, 브라우저 시각/접근성 검증 미실시**.
- 실제 사용자 경험 최종 검증은 Replit에서 빌드한 후 `docs/UX_ACCEPTANCE_V11.md`에 따라 수행해야 한다.
